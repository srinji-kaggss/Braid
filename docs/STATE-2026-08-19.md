## ── What a fresh measurement adds ────────────────────────────────

### The one declared consumer never imports the crate

`logic-os-kernel/kernel/Cargo.toml:213-214` declares `braid-ir` and
`braid-vocab-cms` as path dependencies. A search for `braid_ir` or
`braid_vocab_cms` across `logic-os-kernel/kernel/crates` returns **nothing**.
The only Braid reference in the kernel is a snapshot test at
`kernel/crates/canvas-syscall/tests/braid_vocab_binding.rs`.

So `D-CONSUMER` is sharper than "zero external consumers": there is **one
declared dependency that resolves, compiles, and is never imported**. A manifest
edge with no `use` is not adoption; it is a reservation. Any estate map counting
that edge — including the one written earlier today at
`~/forge-sdk/docs/DEP-MAP-2026-08-19.md` — overstates L1's reach by exactly one.

### The browser collapse is unstarted, not half-done

`DEBT_REGISTER` records a parallel `BraidTerm` enum in the browser engine with a
steer note delivered and not acted on. Measured today: `docs/BRAID_STEER.md`
exists in `next-gen-browser-engine`; **`BraidTerm` appears in no `.rs` file
there**. Whatever the parallel enum was, it is not in the tree now. That is
better news than the register implies — there is no divergent copy to collapse,
only a pipeline to wire. The engine's own README already commits to it: *"JS →
Braid IR → validated WASM instead of a JS VM."*

This matters more now that the browser lane is converging on upstream gosub. A
contribution path into an external project is a much harder place to introduce
a Braid dependency later than it is to design one in now.

### Two tracked build artifacts — removed

`crates/braid-project/liblib.rlib` (28 KB) and
`crates/braid-vocab-rust/liblib.rlib` (17.6 KB) were tracked in the working

## ── The distinction to make before day-0 starts ──────────────────

Two different things in this estate are called a stdlib. They share no code, no
repo, and no completion criterion. Conflating them will build the wrong one.

| | **stdlib+ — `lgwks_std`** | **the Braid vocabulary stdlib** |
|---|---|---|
| what it is | a Rust utility library so the four authorized Rust repos need **no default dependency outside `std` + `lgwks_std`** | the library of **semantic terms** the contract is written in — what a capsule is allowed to say |
| lives in | a new repo, `lgwks-std` (proposed, does not exist) | `braid-vocab-*` crates in this repo |
| tracked as | `docs/handoffs/2026-08-17-lgwks-std-proposal.md` | `D-VOCAB` in `DEBT_REGISTER` |
| current state | census done across 24 manifests: `thiserror` 16 files, `hex` 11, `uuid` 9, `anyhow` 4, `chrono` 4 → ELIMINATE; `blake3`/`sha2` 8 → VENDOR; `serde` 31, `tokio` 13, `regex` 3 → BOUNDARY | 16 pure JS terms; expression-only, no statements or identifiers; CMS + web + rust vocabularies alongside |
| blocked on | a Director ruling: repo name and location, plus authorization to write the four repos | literal payloads — `Strand` carries no operand, D8-locked substrate work |
| what "done" means | dependency counts fall (Braid 119, forge-sdk 331, forge-harness 560, rust-ai-stack 1025 resolved crates today) | a capsule can express a real program, not an expression |

**Read of the day-0 ask:** *"stdlib+"* is the left column — Rust's stdlib **plus**
`lgwks_std`, exactly the proposal's phrasing *"no default deps outside of rust
stdlib and lgwks_std."* *"Braid semantic contract"* is the right column plus the
verifier that enforces it. Both are day-0; they are separate tracks and should
not be sequenced as one.

The left column is hygiene with a hard number attached and is executable as soon
as the repo exists. The right column is the product.

## ── What actually remains, ranked ────────────────────────────────

1. **A publish path.** The registry export at `~/wwfd/braid-registry/` holds 4
   crates at `0955e05`, is stale versus HEAD, and has **no regeneration
   script**. Until a contract is publishable, nothing above L1 can depend on
   one, and the `logic-os-kernel` path dependency keeps the kernel unbuildable
   on any checkout without Braid as a filesystem sibling. This is the top item
   and it is small.

2. **One real consumer, live-wired.** `DEBT_REGISTER`'s own priority 3, and now
   the only thing standing between "verified substrate" and "dependency." The
   kernel is the cheaper target — the manifest edge already exists, so the work
   is replacing a snapshot test with an import. The browser is the more valuable
   one, and its window is closing as that lane merges upstream.

3. **The keel duplicate-concept gate (`A3`).** Killing the nine reimplementations
   is blocked on consumership *and* on a gate that does not exist. Keel is the
   most complete tool in the estate; this historical snapshot said it ran in
   Braid CI, but that integration was later retired and is open again under #78.
   **This is the lever that makes the semantic contract binding before a runtime
   exists** — keel can refuse a duplicate concept at CI time in every repo, which
   is enforcement without adoption. It is the shortest path from "Braid is
   correct" to "Braid is obeyed."

4. **`lgwks_std`, on the Director's ruling.** Blocked only on a name, a location,
   and write authorization. The census is done; the work is mechanical.

5. **Literal payloads (`D8`).** The substrate unit that unblocks a vocabulary
   worth calling a stdlib. Everything in the right-hand column above waits on it.

6. **`U15` Lean⇄verifier conformance, then `U7` runtime.** Unchanged from the
   register. `U7` stays blocked on the kernel WASM epic; a minimal Braid-direct
   interpreter remains the alternative if that epic does not move.

Items 1–3 are the ones that change Braid's position in the estate. Items 4–6 are
already correctly ordered in `DEBT_REGISTER` and need no re-litigation.
