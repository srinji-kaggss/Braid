# Braid threat model — "all the shitty stuff"

**Scope**: the framework's own failure modes and abuse paths — what breaks,
who abuses it, and which lock/unit closes it. Kernel-level threats (tenant
isolation, attestation, E2EE) are out of scope here; Braid inherits those
postures by riding the kernel (D10). Each entry: attack/failure → consequence
→ mitigation → where it's pinned.

Sources: kernel hacker-pass history (the best predictor of our failure modes is
our own record), research baseline §12–§15, ADR-066's red-team findings, the
DiD slop taxonomy (`laws/governance/ai-code-defense-in-depth.md`).

---

## T1 — Vocabulary escape hatches
A term that smuggles open-ended power: a "run query" strand carrying SQL, a
"fetch" strand carrying a freeform URL, a string param later interpreted as
code downstream. One such term re-opens everything the closed vocabulary
closed. *(ADR-066's own red-team finding: closing actions alone leaks via
params.)*
**Mitigation**: the type universe contains no interpretable-code type;
outbound destinations are the kernel's typed `EgressDestination` only; a
conformance test enumerates the registry and rejects param schemas admitting
free-form interpreted content. New terms = version bump + review (D11).
**Pinned by**: U1/U3 conformance tests; acceptance #14.

## T2 — Verifier/generator collusion (trusting trust)
The verifier shares serialization or normalization code with the SDK/codegen;
a parse-differential admits bytes the verifier judged differently than the
runtime executes. Or the verifier is generated by the same AI that authors
capsules, baking in a shared blind spot.
**Mitigation**: D9 — independent implementation; byte-level KAT parity as a
build gate (acceptance #13); fuzzed decode-parity between `braid-verify` and
any other decoder; verifier kept small + minimal-dependency.
**Pinned by**: U1 KATs, U3 parity suite, U9 hacker pass.

## T3 — Canonical-encoding malleability
Two byte-strings → one CID-claimed capsule, or one byte-string → two parses.
*This already happened in-kernel*: the A4.8 governance ledger's first
implementation accepted reordered/junk-padded artifacts whose signatures
verified.
**Mitigation**: D8 — canonical CBOR subset, definite lengths, sorted keys, no
floats; **bijection guard** (decode → re-encode must equal input bytes, else
reject); KAT vectors pinned before any other code consumes the encoding.
**Pinned by**: U1 (bijection + KAT + fuzz round-trip).
**U9 finding (closed, was High)**: the bijection guard operates at bytes↔Value;
the Value→struct projection initially dropped *unknown keys in nested maps*
(braid, strand, registry, term — only the top-level capsule map was strict).
A key smuggled into a sub-map yielded distinct bytes that still parsed, with
the CID committing to the re-encoded (clean) projection rather than the
admitted bytes — sub-map malleability. Fixed by `Value::require_only_keys`
enforced at *every* map level, plus an "accepted bytes round-trip identically"
invariant test. Regression: `braid-ir/tests/malleability.rs`
(`smuggled_key_in_*`), verifier gate `braid-verify` scenario_6b.

## T4 — Manifest ≠ behavior gap
The rendered manifest is honest but stale/detached: codegen consumed different
IR than the manifest renderer, or the artifact was swapped post-admission. The
human approves a manifest that doesn't describe what runs.
**Mitigation**: D12 — manifest derived from the admitted capsule CID; the
admission record binds (capsule CID, manifest CID, artifact CID); runtime
re-derives the manifest at load and refuses on mismatch (acceptance #10).
**Pinned by**: U2 binding tests; U7 load-time re-verification.
**U9 finding (closed, Medium)**: the operator CLI's `render`/`diff` path
strict-decoded canonical capsules but did not require a verifier `ADMIT`
before emitting human-review output. A stale-version or bogus-registry capsule
was rejected by `verify` yet could still be rendered or diffed as an ordinary
manifest, weakening the review gate's fail-closed story. Fixed by making
`render` and `diff` call the verifier first (ambient = declared grants, same
as `verify`'s default) and refuse verifier-rejected capsules before manifest
text is emitted. Regression: `crates/braid-cli/tests/cli_loop.rs`
(`render_refuses_version_skewed_capsule`,
`diff_refuses_version_skewed_capsule`).

## T5 — Capability/effect laundering via composition
Every strand passes its local check; the *path* exceeds: vault-read → pure →
pure → egress. **The kernel already shipped this bug class**: #361's per-hop
rules were proven launderable hop-by-hop and required #431's path-level
monotone taint fold.
**Mitigation**: the verifier's taint stage is path-level from day 1 (never
"per-hop now, path later"); the kernel's trip-wire pattern is replicated:
`path_taint_catches_multihop_laundering` analogue must be RED-then-GREEN under
mutation.
**Pinned by**: U4 + mutation evidence; acceptance #5.

## T6 — Version skew
A capsule admitted under `VOCABULARY_VERSION = 1` runs where a term's
semantics changed in version 2; or two registries disagree about a term_id.
**Mitigation**: D11 — versions pinned in capsule bytes (inside the CID
preimage); admission refuses mismatch absent a migration proof; vocabulary
bumps are conscious events (existing kernel pin-test pattern).
**Pinned by**: U3; acceptance #7.

## T7 — Narrated-not-enforced bounds (the repo's named slop class)
Declared budgets/bounds that nothing enforces — the build-state ledger's
recurring finding ("durable-before-trusted now type-enforced, not narrated").
A capsule declares `compute ≤ 20ms` and runs forever.
**Mitigation**: bounds compile into runtime guards (WASM fuel/limits mapping —
OQ1); every bound claim in docs/tests requires enforcement evidence; budget
exhaustion is deterministic kill + evidence (acceptance #9).
**Pinned by**: U5 exhaustion tests; ledger evidence discipline (D13).

## T8 — Float/nondeterminism poisoning
IEEE floats (NaN canonicalization, platform rounding) or ambient
nondeterminism (time, random, iteration order) break replay and
canonical-form, silently forking CIDs across platforms.
**Mitigation**: D8 — no floats in the IR, fixed-point only (kernel precedent:
`intent_projection.rs` u64 fixed-point); all nondeterminism enters as typed
effects through kernel syscalls (trusted clock, entropy engine); BTreeMap-only
internal ordering (kernel convention).
**Pinned by**: U1 type-universe tests; acceptance #8.

## T9 — Replay/provenance gaps
Admitted-once, mutated-later: artifact store serves different bytes than were
verified; or a capsule replays an old confirmation.
**Mitigation**: content-addressed artifact store (CID lookup only); runtime
admission re-verifies at load (D3 final stages); confirmations are one-shot
and payload-hash-bound (T10); journal-before-effect inherited from the kernel.
**Pinned by**: U7; acceptance #3, #10.

## T10 — Human-confirmation spoofing / confused deputy
UI shows payload A, confirmation authorizes payload B; or a stale confirmation
is attached to a new capsule.
**Mitigation**: confirm policy binds the **hash of the exact effect payload**
(kernel `IntentToken` pattern; research scenario 3); one-shot, expiring,
scoped to the work object (ADR-073 attenuation).
**Pinned by**: U4 confirm-policy checks; acceptance #3.

## T11 — Toolchain/dependency compromise
A malicious or yanked dependency inside `braid-verify` makes the admission
gate itself the attack surface.
**Mitigation**: minimal-dependency policy for the verifier crate (workspace
dependency factory; no new deps without review); hermetic-build alignment with
ADR-080 attestation when that lands; the verifier is in the kernel CI gate
from U3 onward.
**Pinned by**: U3 dep-allowlist conformance test.

## T12 — Authority creep through review fatigue
Hundreds of small manifest diffs train the human to approve; a widening slips
through.
**Mitigation**: the CI gate (not the human) flags widenings — additions of
capabilities/effect classes are mechanically detected and require an explicit
security-review label; narrowing/no-change diffs are visually distinct.
Red-team requirement: a deliberate widening PR must be caught before v0 ships
(success metric).
**Pinned by**: U6; acceptance #11.
**U9 finding (closed, Medium)**: `manifest_diff` could return an empty delta
set for two different admitted capsules when the changed fields did not alter
capabilities, effect classes, budget, confirmation, or intent. The CLI then
printed `no change`, even though the capsule CID and review-visible evidence
policy had changed. Fixed by emitting neutral deltas for capsule CID and other
review-visible non-widening fields (strand count, cost, irreversible/egress
counts, evidence), so only identical manifests produce `no change`; the
widening gate's exit semantics remain unchanged. Regression:
`braid-render/tests/render.rs::changed_artifact_is_not_reported_as_no_change`
and
`braid-cli/tests/cli_loop.rs::diff_neutral_artifact_change_is_not_no_change`.

## T13 — AI-only path dependence (sovereignty failure)
The pipeline quietly grows steps only an AI can perform (unwritten knowledge,
generated glue), violating human reconstructability.
**Mitigation**: L7 — `braid-cli` is the reference path; acceptance #12 runs
the entire loop CLI-only in CI; docs sufficient for a specialist to author a
capsule by hand are part of U6's AC.
**Pinned by**: U6; acceptance #12.

## T14 — Abstract-acceptance slop / Goodharting the demo
v0 "passes" on toy capsules that exercise nothing real; or the CMS demo is
stubbed until it proves nothing (the hollow-mock finding from A4.4's history).
**Mitigation**: D7 locks the reference workflow to real afternow-port CMS
actions; U8's ACs require real kernel append/projection round-trips with
journaled evidence, not mocks; U9 hacker pass explicitly hunts hollow tests.
**Pinned by**: U8 ACs; U9.

## T15 — Boundary erosion (extraction debt)
Braid crates grow imports into kernel internals; extraction to its own repo
becomes a rewrite; worse, Braid starts *being* a second authority system
(parallel grants, parallel hashing) — the #556 fork re-created internally.
**Mitigation**: D3/D10 — declared-contracts-only dependency rule enforced by a
conformance test (the kernel's `test_module_boundary_contract.rs` pattern);
no new hash domains outside `lw.braid.*`; no capability semantics outside the
kernel's.
**Pinned by**: U1 boundary conformance test.

## T16 — Scope stampede (the meta-threat)
The framework tries to become the blue-sky language now: grammar bikeshedding,
editor work, stdlib sprawl, "just one little eval for templates." Every dead
end in research baseline §22 is a face of this.
**Mitigation**: D6 locked non-goals; §16 trigger gating for syntax; "no issue,
no work" + minimal-patch-set law; any agent may block scope creep including
the Director's (CODEBOOK §8) — decompose, log, sequence.
**Pinned by**: D6/D13; orchestrator discipline.

## Residual risks (accepted, on record)

- **R1**: `VOCABULARY_VERSION = 1` may churn before 2 workflows exist;
  capsules pin versions so churn is breaking-but-visible (ADR-088
  Consequences).
- **R2**: P3 depends on the kernel WASM runtime that does not exist yet; P1–P2
  are designed to be valuable standalone (verifier + CI gate run without a
  runtime).
- **R3**: the manifest renderer is itself trusted presentation code; D12's
  re-derivation check bounds, but does not eliminate, rendering bugs — U9 must
  include manifest-spoofing attempts.
  **U9 finding (closed, Medium)**: `render_text` emitted user-controlled
  string fields (`intent`, `evidence`) verbatim into the line-oriented
  `key: value` manifest. A `\n` in `intent` injected forged `capsule:` /
  `capabilities:` / `intent:` lines *above* the real binding CID and
  *before* the true `capabilities:` line — an admitted capsule could present
  a reviewer with a benign-looking manifest whose real authority was buried
  below forged lines. Same vector via `evidence`. (The capsule admits because
  intent content is not a v0 gate — D30: intent-coherence is advisory, not
  blocking; the exploit is against the *review object*, not the admission
  gate.) Fixed by `escape_field` at the emission boundary
  (`braid-render/src/lib.rs`): `\` / `\n` / `\r` / `\t` are escaped so one
  logical field always renders on exactly one physical line; the only raw
  newlines in the output are the ones the emitter inserts between fields.
  Regression: `braid-render/tests/render.rs`
  (`newline_in_intent_cannot_inject_manifest_lines`,
  `carriage_return_in_intent_cannot_inject_manifest_lines`,
  `newline_in_evidence_cannot_inject_manifest_lines`,
  `backslash_in_intent_is_escaped_unambiguously`) and end-to-end
  `braid-cli/tests/cli_loop.rs::render_escapes_newlines_so_manifest_cannot_be_spoofed`.
